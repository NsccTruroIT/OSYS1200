Packaging & Installing
Software in Windows 11

From legacy Setup.exe wizards to silent .msi deployments, containerized MSIX/AppX packages, and modern CLI automation with winget.

Today's Goal: Understand what happens under the hood when software installs on Windows—and how administrators deploy, audit, and remove apps without clicking Next → Next → Finish.
Under the Hood

What Does an Installer Actually Do?

Installing software is rarely just copying files. A standard Windows installer touches four layers of the OS:

1. Filesystem

Extracts binaries to C:\Program Files (64-bit) or Program Files (x86), plus shared runtime DLLs.

2. Registry

Writes app settings, file associations (HKCR), and Uninstall metadata in HKLM.

3. Services & Drivers

Registers background Windows services (e.g., updaters), scheduled tasks, or kernel drivers.

4. Shell & PATH

Creates Start Menu shortcuts, Desktop icons, and adds CLI tools to the system PATH.

Why "Just Deleting the Folder" Breaks Windows: Deleting C:\Program Files\App leaves orphaned Registry keys, broken background services, and phantom entries in Installed apps.
Where Windows Tracks Apps

How Does Settings Know What's Installed?

Every traditional installer writes an entry into the Windows Registry Uninstall key:

HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall
HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Uninstall

Key Values Written

  • DisplayName → App name shown in Settings
  • DisplayVersion → Version number for patching audits
  • Publisher → Vendor name
  • UninstallString → Exact command Windows runs when you click Uninstall

Why Admins Care

  • Inventory scripts and tools like Intune or SCCM read these keys to verify software versions.
  • winget list cross-references these Registry entries to track installed Win32 apps.
Package Formats

The 4 Windows Packaging Formats

1. Traditional Setup.exe

  • A compiled executable running a custom installer engine (NSIS, Inno Setup, InstallShield).
  • Each vendor invents their own command-line switches.

2. Windows Installer (.msi)

  • Not an executable—it's a structured relational database interpreted by Windows (msiexec.exe).
  • Built for enterprise standardization & clean rollbacks.

3. UWP / AppX

  • Sandboxed Universal Windows Platform package (Microsoft Store apps like Calculator, Whiteboard).
  • Isolated filesystem & registry virtualization.

4. Modern MSIX

  • Microsoft's modern unified container format for Win32, .NET, and UWP apps.
  • Supports delta updates, mandatory digital signing, and 100% clean uninstalls.
Deep Dive 1

Legacy Setup.exe (The Wild West)

Strengths

  • Total Flexibility: Vendors can bundle custom splash screens, prerequisite installers (.NET, C++ redistributables), and complex pre/post scripts.
  • Ubiquitous: Still the most common format downloaded by consumers from the web.

The Admin Headache

  • No Universal Silent Flag: Is it /S (case-sensitive!), /silent, /verysilent, or /qn?
  • Registry Rot: Messy uninstallers often leave orphaned files and Registry entries behind.
  • Harder to Automate: Requires testing or wrapping before fleet deployment.
Pro Tip: Running setup.exe /? in a terminal often reveals the hidden silent switches—if the vendor bothered to document them.
Deep Dive 2

Windows Installer (.msi) & msiexec.exe

Because .msi files are databases processed by the built-in Windows Installer service, every .msi shares identical administrative flags.

Standardized Flags

  • /i → Install package
  • /x → Uninstall package
  • /quiet (or /qn) → Zero UI / unattended
  • /norestart → Prevent surprise reboots
  • /l*v install.log → Full verbose logging

Enterprise Superpowers

  • Transactional Rollback: If an install fails at 90%, Windows reverts every file and Registry change cleanly.
  • Transforms (.mst): Admins can override defaults (license keys, install paths) without modifying the vendor's signed .msi.
Deep Dive 3

AppX & MSIX (Containerized Apps)

How Containerization Fixes "WinRot"

  • Apps write their files to protected folders under C:\Program Files\WindowsApps.
  • Registry writes go into an isolated, app-specific virtual registry hive—not shared HKLM.
  • Result: Uninstalling removes 100% of the app's footprint cleanly.

Security & Trust

  • Mandatory Digital Signature: Windows refuses to install an unsigned MSIX package unless sideloading/dev certs are explicitly trusted.
  • Block-based Updates: Only changed 64KB blocks download during app updates.

Deployment at Scale

How Admins Deploy Software Today

You don't walk around with a USB stick clicking Next on 500 laptops. Modern Windows administration relies on four deployment layers:

Package Managers (CLI)

  • winget: Native Windows 11 CLI package manager (backed by Microsoft's curated repository).
  • Chocolatey: Mature PowerShell-based package manager widely used in DevOps and Windows automation.

MDM & Enterprise Toolkits

  • Intune / Company Portal: Cloud MDM pushing .msi, .msix, and Store apps—plus a self-service Company Portal for approved apps.
  • PSAppDeployToolkit (PSADT): Industry-standard PowerShell wrapper for pre-install checks, closing open apps, and logging.

winget: Windows Package Manager

Think of winget as apt or dnf for Windows—handling discovery, silent downloads, and upgrades from PowerShell.

# Search for an application ID
winget search PowerToys

# Install silently from the official winget repository
winget install Microsoft.PowerToys --source winget

# Check installed packages or upgrade everything at once
winget list
winget upgrade --all
Lab 6 Tip: If you already installed PowerToys during Lab 5, run winget upgrade Microsoft.PowerToys or winget list Microsoft.PowerToys to verify it via CLI!

Silent .msi Deployment with msiexec

# Run in Command Prompt (Admin) from %USERPROFILE%\Downloads
msiexec.exe /i 7z2409-x64.msi /quiet

# Verify in Settings → Apps → Installed apps, then silently remove:
msiexec.exe /x 7z2409-x64.msi /quiet
Why Command Prompt instead of PowerShell?
PowerShell can misinterpret mixed slashes and arguments passed to legacy Win32 tools like msiexec.exe unless carefully quoted or invoked with Start-Process. Using cmd.exe avoids argument-parsing surprises.
Lab 6 Connection • Activity 7

Managing Store / UWP Apps in PowerShell

Store apps don't use msiexec—they are managed as AppX packages via PowerShell.

# List all Store/UWP packages installed for your user
Get-AppPackage

# Filter using wildcards for a specific app
Get-AppPackage -Name *Todos*

# Pipe the package object directly to remove it cleanly
Get-AppPackage -Name *Todos* | Remove-AppPackage
Admin Use Case: Sysadmins use this exact pipeline pattern in provisioning scripts to de-bloat consumer apps from enterprise Windows 11 images.
Summary

Key Takeaways for Today's Lab

  • Installers touch Files, Registry, Services, and PATH—never "uninstall" by deleting folders.
  • .msi gives admins uniform silent control (/i, /x, /quiet) and safe transactional rollbacks.
  • AppX / MSIX isolate apps in containers so uninstalls leave zero Registry clutter.
  • winget & PowerShell automate the lifecycle—turning multi-step GUI clicks into repeatable one-liners.
