Part 1 • Booting

Legacy BIOS/MBR vs. Modern UEFI/GPT

Feature Legacy BIOS + MBR (Gen 1) UEFI + GPT (Gen 2 — Win11 Required)
Firmware Interface 16-bit real-mode BIOS, executes MBR boot sector Modern 64-bit UEFI runtime, reads FAT32 ESP directly
Disk Partitioning MBR (max 2 TB, 4 primary partitions) GPT (up to 9.4 ZB, 128 partitions, redundant header)
Boot Security No cryptographic boot verification Secure Boot checks signed bootloaders (bootmgfw.efi)
Hardware Root of Trust Optional / legacy TPM 2.0 required for Windows 11 & BitLocker key sealing
Hyper-V Rule: Always choose Generation 2 for Windows 11 VMs. Generation 1 emulates Legacy BIOS and has no virtual TPM or Secure Boot.
Part 1 • Booting

The Windows 11 UEFI Boot Chain

1. UEFI + Secure Boot
→
2. ESP: bootmgfw.efi
→
3. BCD Store
→
4. winload.efi
→
5. ntoskrnl.exe & Logon

Key Boot Components

  • ESP (EFI System Partition): Hidden FAT32 partition holding \EFI\Microsoft\Boot\bootmgfw.efi and the BCD file.
  • Boot Configuration Data (BCD): Firmware-independent database replacing old boot.ini.
  • winload.efi: Loads the kernel (ntoskrnl.exe), HAL, and boot-start drivers.

Inspecting Boot Config (Lab 4-1 Callback)

# Run in elevated PowerShell or CMD
bcdedit /enum

# Look for:
# path  \EFI\Microsoft\Boot\bootmgfw.efi
# path  \WINDOWS\system32\winload.efi
Part 2 • Installation

Windows 11 Setup Phases & Options

Clean Install vs. In-Place Upgrade

  • Clean Install: Boots from USB/ISO/PXE into WinPE, wipes or uses unallocated space, applies fresh install.wim. Zero legacy clutter.
  • In-Place Upgrade: Runs setup.exe from inside Windows; preserves apps, user profiles, and settings.

The 4 Setup Passes

  1. Windows PE: Partitions disk, formats NTFS/ESP, lays down image.
  2. Offline Servicing: Injects drivers/updates before first boot.
  3. Specialize: Generates unique SID, computer name, Plug & Play.
  4. OOBE: Region, network, user account, privacy toggles.
Notice: Windows Setup doesn't "copy files one by one" like an app installer—it expands a compressed WIM/ESD image directly onto the partition!
Part 2 • Installation

Hyper-V Reference VM Checklist

VM Creation Settings

  • Name: Win11-Reference
  • Generation: Generation 2 (UEFI)
  • Memory: 4096 MB (4 GB)
  • Processors: 2 virtual CPUs
  • Virtual Hard Disk: 64 GB or larger (new VHDX)
  • Media: Official Windows 11 ISO

Security Settings (Before Power-On!)

  • Open VM Settings → Security.
  • Check Enable Secure Boot (Template: Microsoft Windows).
  • Check Enable Trusted Platform Module (TPM).
Skipping TPM triggers: "This PC can't run Windows 11."
Part 2 • Installation

OOBE vs. Audit Mode (Ctrl + Shift + F3)

Why Not Finish OOBE?

  • Completing OOBE creates a user profile, binds a Microsoft Account (unless bypassed with OOBE\BYPASSNRO), and starts background Store app updates.
  • Those Store app updates are a top cause of Sysprep failures later!

Audit Mode Workflow

  • Stop at the Country or Region screen.
  • Press Ctrl + Shift + F3 (or Fn + Ctrl + Shift + F3).
  • VM reboots into the built-in Administrator account with the Sysprep dialog open.
  • Stage software/drivers cleanly without creating user profiles.
Part 3 • Sysprep

Generalizing with Sysprep

C:\Windows\System32\Sysprep\sysprep.exe prepares a Windows installation to be cloned or captured.

Why Check "Generalize"?

  • Every Windows install has a unique SID (Security Identifier)—separate from its hostname.
  • Cloning without Generalize creates duplicate SIDs, breaking Active Directory trusts, WSUS, and security tokens.
  • Generalize strips the SID, hardware-specific drivers, and event logs so the next boot runs Specialize fresh.

Required Sysprep Settings

  • System Cleanup Action: Enter System Out-of-Box Experience (OOBE)
  • Generalize: Checked
  • Shutdown Options: Shutdown
Leave it Off! Booting the reference VM again starts OOBE/Specialize and ruins its generalized state. Always test copies, never the master!
Part 3 • Sysprep

Sysprep Troubleshooting & Logs

Where to Look When Sysprep Fails

Sysprep writes detailed logs inside the VM at:

C:\Windows\System32\Sysprep\Panther\setuperr.log
C:\Windows\System32\Sysprep\Panther\setupact.log

Always read setuperr.log first—it names the exact blocking Appx package or service.

Common Sysprep Blockers

  • Microsoft Store AppX updates: An app updated for one user, not provisioned for all users.
  • BitLocker enabled: Encryption must be suspended/off before generalizing.
  • Rearm limit: Activation rearm count exceeded (slmgr /dlv).
Part 4 • DISM

DISM & Windows Image Formats

DISM (Deployment Image Servicing and Management) is the Swiss Army knife for Windows .wim, .esd, and live OS servicing.

File-Based Imaging (.wim / .esd)

  • .wim (Windows Imaging Format): File-based, supports multiple editions (indexes) in one file using single-instance storage, and can be mounted read/write.
  • .esd (Electronic Software Download): Higher compression (smaller ISOs), read-only until exported to .wim.

Inside Your Windows 11 ISO

# List all Windows editions inside the ISO
dism /Get-WimInfo /WimFile:D:\sources\install.wim

# (Consumer ISOs often use install.esd)
dism /Get-WimInfo /WimFile:D:\sources\install.esd
Part 4 • DISM

Offline Imaging: Capture, Mount & Apply

# 1. Capture a generalized C:\ volume (from WinPE) into a .wim image
dism /Capture-Image /ImageFile:E:\Images\Win11Ref.wim /CaptureDir:C:\ /Name:"Win11 Pro Ref"

# 2. Mount an offline .wim to inject drivers or updates without booting it
dism /Mount-Image /ImageFile:E:\Images\Win11Ref.wim /Index:1 /MountDir:C:\Mount
dism /Image:C:\Mount /Add-Driver /Driver:C:\Drivers /Recurse
dism /Unmount-Image /MountDir:C:\Mount /Commit

# 3. Apply the captured .wim to a freshly partitioned target drive (from WinPE)
dism /Apply-Image /ImageFile:E:\Images\Win11Ref.wim /Index:1 /ApplyDir:W:\
After /Apply-Image: You run bcdboot W:\Windows /s S: /f UEFI to write the UEFI boot files onto the target ESP!
Part 4 • DISM

Online Servicing: Component Store Repair

You also use DISM on a running Windows system (/Online) to verify and repair the Windows Component Store (C:\Windows\WinSxS).

# Quick check: has the component store already been flagged as corrupted?
dism /Online /Cleanup-Image /CheckHealth

# Deep scan: actually scans component store files for corruption
dism /Online /Cleanup-Image /ScanHealth

# Repair: downloads clean files from Windows Update (or a /Source WIM)
dism /Online /Cleanup-Image /RestoreHealth

# Then verify protected OS system files
sfc /scannow
Best Practice Order: Always run DISM /RestoreHealth before sfc /scannow—SFC pulls its replacement files from the Component Store that DISM repairs.
Summary

Key Takeaways for Lab 8

  • Booting: Windows 11 requires UEFI/GPT + Secure Boot + TPM 2.0; bootmgfw.efi → BCD → winload.efi → kernel.
  • Audit Mode (Ctrl + Shift + F3): Stage a clean reference VM without creating user profiles or triggering Store updates.
  • Sysprep (OOBE + Generalize + Shutdown): Strips SIDs and hardware bindings; leave the master VM Off.
  • DISM: Works both offline on .wim/.esd images (/Get-WimInfo, /Capture-Image, /Apply-Image) and online (/CheckHealth, /ScanHealth, /RestoreHealth).
